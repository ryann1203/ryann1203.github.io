DoLog — 대학 졸업전시 아카이빙 플랫폼 운영 중

2025.09 — 현재

대학 졸업전시의 작품과 작가 정보를 기록하는 아카이빙 플랫폼을 개발하고, 서버 배포와 운영을 담당했습니다.

  • 공동 작가 동시 제외 시 작품이 전시에 남는 문제를 전시 단위 비관적 잠금으로 해결했습니다. 빈도가 낮고 정합성이 중요한 관리자 요청은 같은 전시에서만 순차 처리하도록 DELETE와 PATCH를 통일했습니다. MySQL 8.4 Testcontainers 동시 테스트를 경로별 10회 수행해 마지막 작가 제외 후 작품의 전시와 구역 연결 해제를 검증했습니다.
  • 작품, 전시 구역, 공동 작가와 작가 프로필을 fetch join으로 함께 조회하고 중복 결과를 제거해 N+1 문제를 개선했습니다. 작품명과 작가명 검색에도 같은 조회 방식을 적용했습니다.
  • 작품 기본 정보와 공동 작가, 상세 이미지 변경을 하나의 트랜잭션으로 처리했습니다. 혼재한 로직을 작품 관리, 이미지 처리, 작가 연결, 전시 조회 기능으로 분리했습니다.
  • 가로 1,600px 초과 이미지를 비율에 맞게 축소하고 WebP로 변환해 S3에 저장하는 공통 파일 서비스를 구현했습니다. 파일 형식과 콘텐츠 타입을 통일해 작품, 작가, 전시에서 재사용했습니다.
  • 3개 학과의 전시 아카이브 운영과 타 대학 유료 도입을 경험했습니다. 약 100개 학과에 연락해 요구사항을 조사하고, 개발자의 직접 입력을 줄이는 학과별 관리자 기능을 개발하고 있습니다.

KB HomeDeal — 부동산 거래 의사결정 플랫폼

2026.03 — 2026.08

실거래가와 금융 규정을 결합해 부동산 거래의 적정 가격과 협상 구간을 제시하는 플랫폼의 백엔드를 개발했습니다.

  • 약 600만 건의 매매 및 임대 데이터를 요청마다 집계하던 지도 API를 요약 테이블과 범위 제한 쿼리, 인덱스로 개선했습니다. 새 요약 데이터를 스테이징 테이블에 완성한 뒤 한 번에 교체해 갱신 중 불완전한 데이터가 조회되지 않도록 했습니다.
  • 자연키를 기반으로 SHA-256 생성 컬럼을 구성하고 DB UNIQUE 제약과 INSERT IGNORE로 중복 적재를 막았습니다. 사전 조회에 의존하지 않아 동시 수집과 배치 재실행에서도 동일 거래가 중복 저장되지 않도록 했습니다.
  • 건축HUB 실시간 호출을 Quartz 사전 수집으로 바꿔 외부 API의 500 오류와 지연을 사용자 요청에서 분리했습니다. 하루 최대 300개 아파트를 5개 스레드로 수집하고, 통신 오류는 재시도하되 실제 데이터 미존재만 NOT_FOUND로 구분했습니다.
  • 세금과 LTV, DSR, DTI 규정을 적용 기간이 있는 DB 기준정보로 관리하고 계산, 검증, 서비스 책임을 분리했습니다. 가격 구간별 LTV 때문에 발생하는 매수 상한가 순환참조는 이진탐색으로 해결했습니다.
  • 최대 5,000개 항목을 보관하는 TTL 10분의 Caffeine 캐시를 적용했습니다. 조회 조건, 줌 단계, 좌표를 정규화해 캐시 키를 재사용하고, 동일 키의 동시 캐시 미스는 Cache.get()으로 한 번만 조회하도록 했습니다.
  • 캐시 ON/OFF 비교에서 p95 응답시간을 동 요약 7.84ms → 1.59ms (79.7%), 아파트 마커 8.25ms → 1.72ms (79.2%)로 단축했으며, 총 42,798건의 요청에서 오류율 0%를 기록했습니다.

측정 조건: 요약 테이블이 적용된 로컬 축소 데이터셋의 동일 지도 영역 반복 조회. k6로 10 → 20 → 30 VU의 4분 부하를 캐시 ON/OFF 각각 3회 수행한 중앙값이며, 최대 처리량 비교가 아닌 응답시간 비교입니다.
