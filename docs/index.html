서비스 소개

졸업전시가 끝난 뒤 작품과 작가 정보가 흩어지거나 사라지는 문제를 해결하기 위한 온라인 전시 아카이빙 플랫폼입니다. 여러 학과의 전시를 하나의 서비스 안에서 독립된 아카이브로 운영합니다.

관람객은 작품명과 작가명으로 검색하거나 전시 구역별로 작품을 탐색할 수 있습니다. 작품의 이미지와 설명, 재료와 크기, 공동 작가의 역할을 함께 기록해 전시가 끝난 뒤에도 열람할 수 있도록 했습니다.

데이터 모델과 수정 흐름

작품, 작가, 전시, 전시 구역의 관계를 설계하고 작품 등록과 수정, 조회 API를 개발했습니다. 한 작품에 여러 작가가 참여할 수 있도록 관계 테이블을 두고 작가별 역할도 함께 관리했습니다.

작품 수정은 기본 정보뿐 아니라 공동 작가와 상세 이미지까지 여러 테이블에 영향을 줍니다. 이 변경을 하나의 트랜잭션으로 묶어 일부 정보만 반영되지 않도록 했습니다. 섞여 있던 작품 관리와 이미지 처리, 작가 연결 로직은 기능별로 분리했습니다.

조회와 동시 수정 문제 개선

목록을 불러올 때 작품마다 작가 정보를 다시 조회하는 N+1 문제를 확인했습니다. 필요한 작품과 작가 정보를 함께 가져오도록 조회 방식을 바꾸고, 조인으로 생기는 중복 결과도 제거했습니다.

관리자가 공동 작가를 동시에 제외할 때 작품이 전시에 남는 문제에는 전시 단위 비관적 잠금을 적용했습니다. 빈도는 낮지만 정확성이 중요한 작업이므로 같은 전시의 변경은 순서대로 처리하고, 다른 전시는 동시에 처리할 수 있도록 범위를 제한했습니다. 동시 요청 테스트로 마지막 작가 제외 후 연결이 해제되는 것을 확인했습니다.

이미지 처리와 서비스 운영

원본 이미지를 그대로 저장하면 파일 크기와 전송량이 커지는 문제가 있었습니다. 큰 이미지는 비율을 유지해 축소하고 WebP로 변환한 뒤 S3에 저장하는 공통 파일 서비스를 만들어 작품, 작가, 전시에서 재사용했습니다.

백엔드 배포와 서비스 상태 확인을 담당하며, 구역이 정해지지 않은 작품이나 이미지가 없는 등록 등 실제 전시 데이터의 예외 조건도 보완했습니다.

운영 결과와 확장

6개월간 누적 조회 6,500+회, 활성 사용자 약 900명의 서비스를 운영 중입니다. 3개 학과의 전시 아카이브를 구축하고 타 대학의 첫 유료 도입으로 이어졌습니다.

운영 과정에서는 개발자가 학과별 데이터를 직접 입력하는 방식이 확장의 병목이 됐습니다. 약 100개 학과에 연락하고 담당자와 미팅하며 요구사항을 조사했으며, 현재는 학과가 전시와 작품을 직접 등록하고 관리하는 기능을 개발하고 있습니다.

접근성을 고려한 화면 구성

메뉴 이미지와 이름, 가격이 각각 읽히면 같은 정보를 반복해서 듣거나 원하는 선택지까지 여러 번 이동해야 했습니다. 한 화면에서 하나의 선택을 수행하도록 구성하고, 불필요한 요소와 중복 음성 안내를 줄였습니다.

메뉴, 온도, 옵션, 수량을 순서대로 선택하게 해 현재 해야 할 일을 분명하게 보여주고, 장바구니와 주문 확인까지 같은 흐름으로 이어지도록 했습니다.

주문 상태 관리와 API 연동

여러 페이지로 나뉜 화면에서도 메뉴와 옵션, 수량, 장바구니가 유지되도록 localStorage로 상태를 관리했습니다. 선택한 항목으로 총금액을 계산하고 서버가 처리할 수 있는 주문 데이터로 변환했습니다.

Fetch API로 매장 이용 방식과 주문 내역을 전송하고, 응답의 주문번호를 저장해 표시했습니다. 빈 장바구니와 오류 응답도 처리해 주문 중 문제가 생겼을 때의 흐름을 보완했습니다.
